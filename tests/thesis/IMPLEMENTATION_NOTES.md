### 3. IC `t` field is mislabeled in PRODUCTION_METRICS.json

`PRODUCTION_METRICS.json::ic.m2_ic.t` is `0.0752`, but the actual NW
t-stat for M2 IC in `tables/table_ic.tex` is `-0.77`. The `0.0752`
value matches the **Std** column (col 2), not the t-stat (col 3).
This is a label bug in `scripts/build_metrics.py::parse_table_ic`.

Workaround: the manifest generator no longer emits an `ic_m2_ic_t`
entry. Once you fix `parse_table_ic` to use the right column, you can
re-add `t` to `_IC_LEAF_COL` in `make_manifest.py` and regenerate.

### 4. `january` section selector

The `january` section's PRODUCTION_METRICS keys are
`m2_excl_jan_*`, `m2_full_*`, `mom12_excl_jan_*`, `mom12_full_*`,
but `tables/table_january.tex` has the same row labels (`M2: XGB`,
`Fixed 12-mo mom`) repeated under two `\multicolumn` headers ("Full
sample (baseline)" vs "Excluding January"). `find_in_table` returns
the first match, so `excl_jan` and `full` would both bind to the
same row.

Options:
- Extend `find_in_table` to accept an optional `section_substr` that
  scans only after a marker like `"Excluding January"`.
- Move the source to a CSV (if `scripts/january_exclusion.py` writes
  one).
- Leave it as `source: null` (current behaviour) and rely on prose
  cite checks alone.

8 entries are affected.

### 5. `international` section (72 entries) is `source: null`

Each region has its own CSV (`results/thesis/intl_uk_summary.csv`,
`intl_uk_returns.csv`, etc.) with a different schema. The keys
encode `<region>_<benchmark>_<strat>_<metric>` where
`benchmark ∈ {regional, uspi}`. Backfilling these requires a
region-aware resolver and a CSV-per-region mapping. Mechanical work
but ~100 lines of dict definitions; left for a follow-up since none
of these claims are currently load-bearing in the thesis prose.

### 6. Coverage-gate strict mode

`coverage_report.md` lists ~177 orphan decimals in `latex/*.tex`. Most
are values that would benefit from migration to `\m...` macros (the
infrastructure already exists in `latex/canonical_macros.tex` and
`scripts/build_canonical_macros.py`). Once migration is done:

```bash
THESIS_GATE=strict pytest tests/thesis/test_coverage_gate.py
```

This converts the warning to a hard fail and prevents future drift.
Out of scope for the auto-suite; should be a deliberate prose pass.

### 7. Macro entries with `source: null` (~250)

Every `\m...` macro in `canonical_macros.tex` becomes a manifest entry,
but most have no separate CSV source — they ARE the canonical numeric
value, generated from `PRODUCTION_METRICS.json` via
`scripts/build_canonical_macros.py`. These entries currently have
`source: null` so test_numbers.py only checks their cites.

Two ways to harden:
- Skip generating macro entries whose `id` already collides with a
  PRODUCTION_METRICS entry (would deduplicate ~140 of the ~250).
- Add a `source_link: macro` field that asserts the macro value
  matches the corresponding PRODUCTION_METRICS leaf.

Both are mechanical; neither is urgent.
