# International HMM Feature Selection (UK + JP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run a CV-based HMM feature-selection procedure separately on UK and JP panels, refit the production HMM at the per-region selected features, rerun the cross-sectional pipeline, and update the N1 thesis section so the regional-π baseline reflects a region-specific selection (removing the asymmetric-tuning caveat that would otherwise need to be added).

**Architecture:** A parallel `scripts/hmm_feature_selection_intl.py` adapts the existing US `scripts/hmm_feature_selection.py` (the 4-pass test-period-evaluated procedure used to pick US production features) for international panels via a `--region UK|JP` flag, a smaller candidate pool (DD, VOL, DISP, REL_N, BANK_REL), and region-aware panel/output paths. The 4 passes are: (1) HMM quality screen across all combos, (2) portfolio test on survivors with test-period Sharpe, (3) definitive validation on top-3, (4) economic validation. After Pass 2, the **user manually picks** the feature set for each region from the ranked candidates (rather than auto-selecting the top combo). The chosen features are then fed to `scripts/hmm_intl.py` to regenerate `data/<region>_panel_with_regimes.parquet`, and `scripts/cross_sectional_intl.py` reruns the four cross-sectional configurations (UK regional, UK US-π, JP regional, JP US-π). International candidate pool has 15 combinations of size 1-4 (vs US's 93), so wall-clock per region for the full 4-pass is ~90-120 minutes.

**Tech Stack:** Python 3.12 (pandas, statsmodels, xgboost, multiprocessing), existing scripts in `scripts/`, parquet panels in `data/`, output CSVs/JSON in `results/thesis/`. CLAUDE.md project conventions apply (pull before push; never force-push or skip hooks; cap concurrent work at 6 of 8 cores per active job; no em-dashes in `.tex`; snapshot baselines before overwriting `results/`).

## Risks / decision points

- **HMM convergence on the JP panel**: JP has a structurally weak post-bubble period; some feature combinations may produce degenerate single-state HMMs. The CV script should skip-and-warn rather than crash on convergence failures. Verify in the smoke test.

- **Smaller candidate pool means less "exploration"**: With only 15 combinations vs the US's 93, the international winner is more likely to be near a corner of the candidate space. If a clear winner emerges, this is fine; if all combinations cluster within fold-noise, the conclusion is "regional feature choice is not pinned down by CV" — which is itself a result worth stating in the thesis appendix.

- **Stock-panel column-name mismatch**: international stock panels likely use different identifier columns than CRSP (`gvkey` vs `permno`). Step A5.6 is the most failure-prone task.

- **Result reverses the headline**: if regional π post-CV beats US π in either region, the global-financial-cycle claim weakens. This is a plan that must withstand the result it produces; the thesis prose update step (C7) needs flexibility to accommodate either outcome.
